# 접두사 허용 규칙은 권한 경계가 아니다

> 명령 접두사로 만든 허용 목록은 문자열 비교일 뿐 플래그를 해석하지 않는다. "읽기 전용 하위 명령"을 허용했다고 믿어도, 같은 하위 명령이 가진 쓰기·실행 플래그까지 전부 함께 열린다.

## 왜 그렇게 동작하나

도구에 명령 실행 권한을 줄 때 흔히 쓰는 방식이 접두사 허용 규칙이다.

```
allow: ["Bash(git log *)", "Bash(find:*)", "Bash(gh api *)"]
```

이 규칙의 매칭은 **접두사 문자열 비교**다. `git log ` 로 시작하기만 하면 뒤에 무엇이 오든 통과한다. 규칙 엔진은 뒤따르는 문자열을 파싱하지 않고, 그게 플래그인지 인자인지도 구분하지 않는다.

문제는 "읽기 전용"이라고 알려진 하위 명령 대부분이 **쓰기·실행 플래그를 함께 갖고 있다**는 점이다.

| 겉보기 | 실제로 가능한 것 |
| --- | --- |
| `git log` / `git diff` | `--output=<file>` 로 임의 경로에 파일 생성 |
| `git branch` | `-D` 삭제, 인자만 주면 생성 |
| `git fetch` | `--upload-pack='<cmd>'`, `ext::<cmd>` 리모트로 임의 명령 실행 |
| `find` | `-exec <cmd> ;` / `-delete` |
| `gh api` | 메서드 지정으로 POST·DELETE·GraphQL 뮤테이션 |
| 아무 `git` 하위 명령 | `-c core.pager=<cmd>` 로 페이저 자리에 명령 주입 |

즉 하위 명령 이름은 능력의 상한이 아니다. 상한을 정하는 건 플래그이고, 접두사 규칙은 플래그를 보지 않는다.

제대로 된 읽기 전용 판정기는 하위 명령마다 **허용 플래그를 열거**해 그 목록에 없는 형태를 거부한다. 접두사 규칙은 그 판정기를 통째로 우회한다 — 같은 명령을 두고 판정기는 거부하는데 규칙은 통과시키는 상태가 된다.

## 확인하는 방법

와일드카드로 끝나는 규칙만 뽑아 하나씩 자문한다: **"이 접두사로 시작하는 문자열 중에 쓰거나 실행하는 형태가 하나라도 있는가?"** 하나라도 있으면 그 규칙은 그만큼의 권한을 이미 준 것이다.

```bash
jq -r '.permissions.allow[]? | select(test("\\*\\)$"))' <설정파일>
```

```
Bash(python3:*)
Bash(gh api *)
Bash(git fetch *)
Bash(find:*)
Bash(~/bin/<runner> <host> *)
```

마지막 줄이 특히 위험한 형태다. 원격 실행 래퍼에 대상 호스트까지만 고정하고 뒤를 열어두면, **그 호스트에 대한 모든 동작**이 승인 없이 통과한다. 조회만 허용하고 싶었더라도 그 의도는 규칙으로 표현되지 않는다.

## 함정

- ⚠️ **"이 하위 명령은 읽기 전용이다"는 와일드카드의 근거가 되지 못한다.** 판정은 하위 명령 단위가 아니라 호출 단위로 해야 한다. 정확한 규칙 여러 개가 넓은 규칙 하나보다 낫다.
- ⚠️ **exact 규칙이라고 자동으로 안전한 것도 아니다.** 규칙 문자열이 로그·기록에서 자동 수집된 것이라면, 그 문자열 자체가 이미 외부 입력에 의해 유도됐을 수 있다. 그 경우 exact 규칙은 "공격자가 고른 명령을 상시 승인"하는 것이 된다.
- ⚠️ **옵션에 숨은 실행 벡터를 놓치기 쉽다** — 설정 오버라이드(`-c key=value`), `--exec-path`, `VAR=x cmd` 형태의 환경변수 대입 접두사, 파이프, 리다이렉션. 전부 한눈에는 읽기 전용처럼 보인다.
- ⚠️ **이름 접두사는 읽기 전용 보장이 아니다.** 외부 도구를 `get_*` / `list_*` 패턴으로 일괄 허용하면, 그 이름을 정하는 쪽은 도구 제공자다. 규칙은 현재 도구뿐 아니라 **앞으로 추가될 같은 이름 패턴까지** 미리 승인한다.
- ⚠️ **허용 규칙은 그 위에 얹은 안전 장치를 건너뛴다.** 판정기든 확인 프롬프트든, 규칙에 걸리면 아예 호출되지 않는다. 그래서 허용 목록은 시스템에서 가장 넓은 권한 경로가 되기 쉽다.
- 규칙은 클릭 한 번으로 쌓이고 지우는 사람은 없다. 수백 개가 되면 아무도 전체를 읽지 않으므로, 주기적으로 뽑아 보는 절차가 없으면 내용을 모르는 채로 유지된다.
