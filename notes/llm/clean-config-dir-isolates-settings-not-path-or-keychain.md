# 빈 설정 디렉터리는 설정만 격리한다 — PATH 와 키체인은 따로 정리해야 한다

> 에이전트 CLI 플러그인을 "남의 환경처럼" 시험하려고 빈 설정 디렉터리(`CLAUDE_CONFIG_DIR`)로 띄우면
> 개인 스킬·훅·전역 지침·설치된 플러그인은 빠진다. 그러나 **셸에서 물려받은 PATH 는 그대로**라서
> 같은 이름의 개인 실행 파일이 남아 있으면 동봉 실행 파일을 시험했다는 보장이 없다. 로그인 정보는 **설정 디렉터리 밖(OS 키체인)** 에
> 남아서, 디렉터리를 지워도 정리되지 않는다.

## 왜 그렇게 동작하나

`[문서]` `CLAUDE_CONFIG_DIR` 은 설정·플러그인 설치 기록·세션 기록이 들어가는 디렉터리를 바꾼다.
처음 띄우면 로그인과 초기 설정을 다시 묻는다. 그래서 빈 디렉터리를 주면 개인 설정이 하나도 없는 상태가 된다.

`[문서]` 플러그인의 `bin/` 디렉터리는 플러그인이 켜져 있는 동안 Bash 도구의 PATH 에 붙는다.
`[추정]` 동봉 `bin/` 이 PATH 앞에 붙는지 뒤에 붙는지는 확인하지 않았다. 어느 쪽이든 같은 이름의 개인 실행 파일이
PATH 에 남아 있으면 "동봉본을 시험했다" 는 보장이 없다. 빈 설정 디렉터리는 PATH 를 건드리지 않는다.

`[실측]` 개인 디렉터리를 항목 단위로 뺀 PATH 로 띄운 세션에서 Bash 도구로 `command -v <이름>` 을 실행하자
플러그인 `bin/` 경로 하나만 나왔고, 그 실행 파일로 쓰기 동작도 정상이었다(셸 시작 파일이 PATH 를 다시 붙이지 않는 환경).

`[실측]` PATH 에서 디렉터리 하나를 빼려고 `${PATH//$HOME\/bin:/}` 같은 치환을 쓰면,
그 디렉터리가 PATH 에 **두 번** 있고 그중 하나가 **맨 끝**(뒤에 `:` 없음)일 때 마지막 것이 남는다.
셸 시작 파일이 여러 군데서 PATH 를 덧붙이면 중복은 흔하다. 항목 단위로 걸러야 확실하다.

`[실측]` macOS 에서 로그인 정보는 키체인에 `Claude Code-credentials-<8자리>` 이름으로 저장된다.
8자리는 설정 디렉터리 절대경로의 SHA-256 앞 8자와 일치했다(경로 1개로 확인, 기본 설정 디렉터리는 접미사 없는 이름).
심볼릭 경로(`/tmp` 와 `/private/tmp`)나 후행 슬래시가 해시를 바꾸는지는 확인하지 않았다.
그래서 설정 디렉터리를 지워도 이 항목은 남는다.

`[문서]` 마켓플레이스를 로컬 디렉터리로 등록하면 플러그인은 그 폴더에서 바로 읽힌다.
`[실측]` `plugin list` 의 `Read from:` 이 작업 폴더를 가리켰고, 코드를 고친 뒤 `/reload-plugins` 만으로 반영됐다.

## 확인하는 방법

PATH 를 항목 단위로 걸러 띄운다.

```
$ PATH="$(printf %s "$PATH" | tr : '\n' | grep -vx "$HOME/bin" | paste -sd: -)" \
    CLAUDE_CONFIG_DIR=<빈 디렉터리> claude
```

치환식이 왜 부족한지 본다.

```
$ printf %s "$PATH" | tr : '\n' | grep -n "$HOME/bin"
23:<home>/bin
37:<home>/bin
$ P="${PATH//$HOME\/bin:/}"; printf %s "$P" | tr : '\n' | grep -n "$HOME/bin"
36:<home>/bin
```

키체인 항목이 그 디렉터리 것인지 확인한다.

```
$ python3 -c "import hashlib;print(hashlib.sha256(b'<빈 디렉터리 절대경로>').hexdigest()[:8])"
eb8b4d80
$ security find-generic-password -s "Claude Code-credentials-eb8b4d80" | grep cdat
    "cdat"<timedate>=... "20261022073357Z\000"
```

생성 시각이 시험 시작 시각과 맞는 것을 먼저 본다. 해시 일치는 경로 1개로만 확인한 보조 근거다.

## 이 노트가 틀렸다면

- **빈 설정 디렉터리로 띄운 세션에서 개인 `~/bin` 실행 파일이 PATH 에 없으면** → CLI 가 PATH 를 정리하는 것이고,
  "PATH 는 따로 정리해야 한다" 는 주장이 틀렸다.
- **설정 디렉터리를 지운 뒤 키체인에 해당 항목이 없으면** → 로그인 정보가 디렉터리 안에 있거나 함께 정리되는 것이다.
- **키체인 항목 접미사가 설정 경로 해시와 다르면** → 이름 규칙 추정이 틀렸다. 생성 시각으로만 판별해야 한다.

## 적용 범위

- macOS, CLI 2.1.3xx 대에서 확인했다. Linux 는 로그인 정보를 파일로 두므로 키체인 부분이 해당하지 않을 수 있다.
- PATH 중복은 셸 설정에 달려 있다. 중복이 없으면 치환식으로도 빠진다.

## 함정

- ⚠️ **"`which` 실행해줘" 라고 해도 모델이 셸을 안 돌리고 파일 검색 도구로 찾아 답할 수 있다.** 두 번 연속 그랬다.
  화면에 셸 실행 대신 검색 표시가 찍혔다면 그 답은 PATH 를 보여주지 않는다. "Bash 도구로 실행해줘" 라고 못 박거나,
  동봉 실행 파일을 실제로 실행하는 단계(예: 쓰기 명령)로 확인한다.
- ⚠️ 빈 설정 디렉터리는 첫 실행 때 테마 선택과 로그인을 묻는다. 사람이 직접 넘겨야 한다.
- ⚠️ 키체인 항목 삭제는 에이전트 권한 정책에서 자격증명 접근으로 막힐 수 있다. 사람이 직접 지운다.
- 💡 이번 시험에서 정리한 것은 셋이다. 시험 세션, 빈 설정 디렉터리, 키체인 항목. 설정 디렉터리와 키체인 밖에 남는 것은 찾아보지 않았다.
