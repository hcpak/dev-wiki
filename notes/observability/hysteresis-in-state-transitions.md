# 히스테리시스 — 상태를 되돌리는 문턱은 진입 문턱보다 높아야 알림이 핑퐁하지 않는다

> 감시 지표가 판정 경계 근처에서 흔들리면, 진입/복귀 문턱이 같은 판정기는 발생↔복구 알림을 반복한다(플래핑).
> 해법은 두 문턱 사이에 간격(히스테리시스)을 두는 것 — 발생은 빠르게, 복구는 충분히 오래 정상일 때만.
> 보일러 온도조절기가 24도에 켜고 26도에 끄는 것과 같은 원리다.

**상태**: 활성
**마지막 검증**: 2026-09-28

## 왜 그렇게 동작하나

`[실측]` 판정 대상이 경계값을 두고 진동하는 상황은 실제로 흔하다. 수집기의 응답 시간이
타임아웃(30s) 근처에서 28~85초를 오가면, 사이클마다 성공과 실패가 섞인다. 판정기가
"에러 카운터 3회 연속 증가 → 발생, 증가 멈춤 → 즉시 복구" 로 대칭이면:

- 실패 몇 사이클 → 🚨 발생 알림
- 우연히 경계 밑으로 몇 번 성공 → ✅ 복구 알림
- 다시 실패 → 🚨 발생 알림 … (반복)

`[실측]` 복구 알림 이후에도 에러 카운터는 계속 증가하고 있었다 — 즉 "복구"는 실제 회복이
아니라 **짧은 소강을 회복으로 오판**한 것이다. 수신자는 "해결됐다"고 믿게 되고, 알림 자체의
신뢰도가 떨어진다(늑대소년 효과).

`[문서]` 히스테리시스는 제어공학의 표준 기법이다. 상태 전이 함수가 현재 상태에 의존하게
만들어(같은 입력이라도 지금 어느 상태냐에 따라 판정이 다름) 경계 진동을 흡수한다.
서모스탯, 슈미트 트리거(전자회로), TCP 혼잡제어의 ssthresh 등이 같은 구조다.

설계 요점:

- **진입(발생) 문턱은 낮게/빠르게** — 문제는 빨리 알아야 한다 (예: 3회 연속 이상)
- **복귀(복구) 문턱은 높게/느리게** — 확실히 나았을 때만 선언 (예: N회 연속 정상, N ≫ 3)
- 💡 N 은 하드코딩하지 말고 설정으로 — 지표의 진동 주기는 시스템마다 다르다

## 확인하는 방법

플래핑 여부는 판정기 로그에서 상태 전이 빈도로 확인한다.

```
04:47 🚨 [발생] ... 파이프라인 이상 (3회 연속 증가)
05:2x ✅ [복구] ... 정상화          ← 이 시점 에러 카운터: 21
05:29 (재확인) 에러 카운터: 35     ← 복구 선언 후에도 계속 증가 = 오판
```

복구 선언 직후 원지표(에러 카운터, 응답시간)를 다시 재면 판정이 맞았는지 갈린다.

## 이 노트가 틀렸다면

- 진입/복귀 문턱이 같은 판정기가 경계 진동 상황에서도 알림을 반복하지 않는다 → 플래핑의 원인이 문턱 대칭이 아니라 다른 것(판정 주기, 지표 자체)이라는 뜻
- 복귀 문턱만 높였는데도 발생↔복구 반복이 그대로다 → 진동 폭이 히스테리시스 간격보다 크다는 뜻 (간격을 넓히거나 지표를 평활화해야 함 — 적용 범위 축소)
- 복귀 문턱을 높였더니 실제 회복 후에도 복구 알림이 오지 않는다 → N 이 지표의 정상 주기보다 길게 잡힌 것 (설계 오류이지 기법의 반증은 아님, 단 "N은 크게"라는 단순 규칙은 틀림)

## 적용 범위

- 이산 사이클로 도는 상태 판정기(타이머형 watchdog, 헬스체크, 알림 규칙) 일반.
- 실측은 1분 주기 타이머 + 카운터 증가 감지형 판정기에서. 연속값 임계(온도·사용률)에도 같은 원리가 적용되나 이번엔 미실측 — `[추정]` 그쪽은 값 자체에 상/하한 두 개를 두는 형태가 된다.

## 함정

- ⚠️ 플래핑은 판정기 결함처럼 보이지만, **지표가 경계에 정확히 걸린 상황 자체가 신호**다 —
  이번 사례에선 타임아웃 값이 실제 응답시간 분포 한가운데 있다는 뜻이었다. 히스테리시스로
  알림을 잠재우는 것과 별개로 경계에 걸린 원인(성능·용량)을 따로 조사할 것.
- ⚠️ 억제(중복 알림 방지)와 히스테리시스는 다르다. "발생 상태 유지 중 재알림 안 함"은 이미
  있어도, 복귀 판정이 성급하면 상태 자체가 리셋되어 억제가 무력화된다.
- 💡 발생/복구가 짝으로 오가는 알림 이력이 하루 2회 이상이면 히스테리시스 부족을 의심할 것.
- ⚠️ `[코드]` 복귀 문턱만 높여서는 **처음부터 교차하는 신호**를 못 잡는다. 진입 판정이 "N회 연속 실패"
  형태면 실패·성공이 한 번씩 번갈아 나오는 신호(실패율 50%)는 연속 실패가 한 번도 없어 발생 자체가
  안 뜬다. 히스테리시스는 "이미 발생한 상태를 유지"하는 장치이지 감지 장치가 아니다.
  💡 `[추정]` 교차 신호까지 잡으려면 진입 판정을 "최근 M회 중 K회 실패" 같은 창(window) 방식으로 바꿔야 할 것이다 (미구현·미검증).
- ⚠️ `[코드]` 발생 상태 안에서의 재알림(쿨다운 만료, 발송 실패 재시도)에 다시 "N회 연속 실패"를
  요구하면, 교차 신호에서는 그 조건이 좀처럼 채워지지 않아 알림이 무기한 밀린다. 발생 상태가
  유지되는 동안의 재알림은 연속 조건 없이 다음 실패 1회로 내보내는 편이 안전하다.
- ⚠️ `[실측]` 판정기가 보는 지표가 원천보다 늦게 반영되면, 복구 알림은 "실제 회복 + N 주기" 가 아니라
  "실제 회복 + 반영 지연 + N 주기" 에 온다. 수집기 내부 카운터를 1분 주기로 읽는 구성에서 N=10 일 때
  원인 해소 후 복구까지 12~13분이었다. 운영 안내에 적는 복구 시간은 이 지연을 더해 잡는다.
