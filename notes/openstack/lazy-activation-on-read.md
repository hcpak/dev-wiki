# 지연 실체화 — 조회 요청이 쓰기를 유발한다

> 상위 리소스를 "등록만" 해두고 실제 백엔드 리소스는 첫 참조 시점에 만드는 설계. 그러면 `GET` 한 번이 네트워크·라우터·포트를 생성하고, 실패 시 되돌리기까지 한다.

## 왜 그런 설계를 하나

논리 리소스(예: 가상 사설망 같은 상위 개념)를 사용자가 만들 때마다 백엔드 리소스 전체를 즉시 만들면, 만들어놓고 안 쓰는 자원이 쌓인다. 그래서 **DB 에 정의만 저장하고, 실제로 쓰이는 순간에 실체화**하는 구조를 택한다. 코드에서는 이런 모양으로 나타난다.

```python
def _hook_get_networks(self, context, filters, ...):
    obj = self._get_logical_obj(context, filters)
    if obj and not obj.activated:
        self._activate(context, obj)     # network/subnet/router 생성 + 외부 IP 할당
    return self.hook.get_networks(context, filters, ...)
```

조회 API 의 훅에 붙어 있다는 점이 핵심이다. 사용자가 보낸 것은 `GET` 이지만, 서버는 그 안에서 다수의 생성 작업을 수행한다.

## 무엇이 관측되나

- **읽기 요청이 비정상적으로 느리다.** 목록 조회 하나가 20초씩 걸린다. 실체화가 라우터 생성·게이트웨이 IP 할당·에이전트 통보까지 하기 때문이다.
- **읽기 요청이 5xx/4xx 로 실패한다.** 그것도 "생성 실패"에 해당하는 에러로 실패한다. 조회만 하는 클라이언트 입장에서는 원인이 보이지 않는다.
- **다른 API 의 실패로 표면화된다.** 어떤 기능(A)을 만들려면 그 앞에 상위 리소스 조회가 들어가는데, 실체화가 거기서 실패하면 사용자는 "A 생성 실패"로 인식한다. **A 의 코드에는 아무 문제가 없다.**
- **실체화에 필요한 자원이 고갈되면 그 상위 리소스에 딸린 모든 기능이 동시에 막힌다.** 예: 인터넷 게이트웨이가 붙은 구성은 라우터 외부 IP 를 반드시 하나 받아야 하므로, 외부 주소 풀이 마르면 게이트웨이를 쓰는 모든 신규 작업이 실패한다. 게이트웨이를 안 붙인 구성은 같은 시각에도 정상 동작한다 — 이 대조가 원인 특정의 핵심 단서다.

## 확인하는 방법

로그에서 실체화 시작 문구를 찾는다. "없으니 만든다" 류의 DEBUG 로그가 경계선이다.

```
$ zgrep -h <server-request-id> <logdir>/<log> | head
... DEBUG ... activate <obj> <id>
... DEBUG ... Network <id> does not exist. create one.   ← 조회가 생성으로 전환된 지점
... INFO  ... Added segment <id> of type vlan for network <id>
```

그 뒤로 이어지는 첫 ERROR 가 실체화 실패 원인이고, 요청 종료 로그(`Completed GET ... in NN sec`)가 사용자에게 돌아간 응답이다.

## 함정

- ⚠️ **"조회는 안전하다"는 가정이 깨진다.** 지연 실체화가 있는 시스템에서는 읽기 API 호출도 쓰기 부하·쓰기 실패·경합을 만든다. 부하 시험이나 모니터링용 폴링을 붙일 때 특히 주의한다.
- ⚠️ **실체화는 대개 멱등하지 않은 롤백을 동반한다.** 실패하면 방금 만든 것을 지우는데, 그 사이 다른 요청이 그 리소스를 쓰기 시작했으면 롤백이 거부되고 원인이 가려진다 → [롤백 중 터진 2차 예외가 원인 예외를 덮어쓴다](rollback-masks-original-exception.md)
- ⚠️ **자동화 테스트는 이 구조를 정면으로 때린다.** 상위 리소스 생성 → 하위 자원 생성 → 기능 생성을 몇 초 안에 이어 붙이고, 서로 다른 스레드로 병렬 실행하기 때문이다. 사람이 콘솔에서 하는 순차 조작에서는 거의 재현되지 않는다.
- 💡 실체화 실패의 진짜 원인은 코드가 아니라 **환경의 자원 고갈**일 때가 많다. 같은 코드가 다른 리전에서 통과한다면 코드 비교보다 자원 잔량(주소 풀, 세그먼트 ID, 쿼터)을 먼저 본다.
