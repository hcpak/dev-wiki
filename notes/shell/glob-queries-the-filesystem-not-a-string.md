# glob 은 문자열 매칭이 아니라 파일시스템 질의다

> glob 은 패턴을 글자에 맞춰보는 것이 아니라, 디렉터리를 실제로 열거하고 각 항목을 `stat()` 하면서
> 이름을 만들어낸다. 그래서 zsh 는 이름 말고 **파일 속성**으로 거르는 glob 퀄리파이어를 가질 수 있고,
> "0건" 이 단순한 빈 결과가 아니라 **디스크에 없다는 사실 보고**여서 별도 처리(에러 / `(N)`)를 받는다.
> regex 에는 둘 다 대응물이 없다 — regex 는 글자만 보기 때문이다.

**상태**: 활성
**마지막 검증**: 2026-08-21

## 왜 그렇게 동작하나

`[문서]` zsh 매뉴얼은 glob 을 "filename generation" 으로 부른다. 매칭이 아니라 **생성**이다.
패턴은 검사 대상이 아니라, 디렉터리를 훑어서 인자 목록을 만들어내는 명령에 가깝다.

`[실측]` 생성 과정에서 각 항목의 타입·권한·시각을 이미 알고 있으므로, 그 정보로 한 번 더 거르는 것이
공짜로 가능해진다. 그게 glob 퀄리파이어다 — 패턴 뒤 괄호에 속성 조건을 적는다.

| 퀄리파이어 | 뜻 |
| --- | --- |
| `(.)` | 일반 파일만 |
| `(/)` | 디렉터리만 |
| `(@)` | 심볼릭 링크만 |
| `(*)` | 실행 권한이 있는 것만 |
| `(m-1)` | 1일 **이내** 수정 |
| `(m+30)` | 30일보다 **오래된** |
| `(L+10M)` | 10MB 보다 큰 |
| `(om[1,5])` | 수정 시각 역순 상위 5개 |
| `(N)` | 0건이어도 에러 내지 않고 빈 값 |

`[문서]` 괄호가 퀄리파이어로 해석되는 조건이 매뉴얼에 명시돼 있다. `BARE_GLOB_QUAL` 옵션이 켜져 있고
(zsh 기본), **괄호 안에 `|` 나 `(` 가 없어야** 한다.

> BARE_GLOB_QUAL — In a glob pattern, treat a trailing set of parentheses as a qualifier list,
> if it contains no `|', `(' or (if special) `~' characters.

이 조건이 중요하다. zsh 패턴에서 괄호는 `(foo|bar).txt` 처럼 그룹/선택지도 뜻하기 때문에, 둘을
구별할 규칙이 필요했던 것이다. 그래서 `*(a|b)` 는 **항상** 그룹이고 절대 퀄리파이어가 아니다.

`[실측]` `(N)` 만 성격이 다르다. 속성 필터가 아니라 에러 억제기다. zsh 는 패턴이 0건이면
`no matches found` 로 실패시키는데(`NOMATCH` 옵션, 기본 켜짐), `(N)` 은 그 패턴에 한해 이를 끈다.
이 동작이 존재하는 이유가 이 노트의 논지와 맞물린다 — glob 의 0건은 "매칭 실패" 가 아니라
"디스크에 그런 파일이 없다" 는 보고이므로, 조용히 넘기면 사고가 되는 경우가 있다.

`[실측]` 반대로 regex 는 주어진 문자열만 본다. 파일의 수정 시각이나 권한은 그 글자열에 들어 있지
않으므로 원리적으로 조건에 쓸 수 없다. `*(.m-1)` 에 대응하는 순수 regex 는 존재할 수 없다.

## 확인하는 방법

zsh 5.9, `setopt bareglobqual`(기본값) 상태. `old.txt` 는 `touch -t 202601010000` 로 과거 시각을 준 것.

```
$ ls
a.txt
b.txt
old.txt
script.sh
sub

$ echo *(.)      # 일반 파일만
a.txt b.txt old.txt script.sh

$ echo *(/)      # 디렉터리만
sub

$ echo *(*)      # 실행권한 있는 것만
script.sh

$ echo *(.m-1)   # 1일 이내 수정된 일반 파일
a.txt b.txt script.sh

$ echo *(.m+30)  # 30일보다 오래된 일반 파일
old.txt
```

0건 처리. 같은 디렉터리에 `nope` 로 시작하는 파일은 없다.

```
$ echo nope*
zsh: no matches found: nope*

$ echo nope*(N)
[  ]
```

bash 와 비교. 퀄리파이어 자체가 문법 오류이고, 0건 처리 방식도 다르다.

```
$ bash --version | head -1
GNU bash, version 3.2.57(1)-release (arm64-apple-darwin24)

$ bash -c 'echo *(.)'
bash: -c: line 0: syntax error near unexpected token `('

$ bash -c 'echo "[" nope* "]"'
[ nope* ]                       # 에러가 아니라 패턴을 글자 그대로 넘긴다

$ bash -c 'shopt -s nullglob; echo "[" nope* "]"'
[ ]
```

## 이 노트가 틀렸다면

- `*(.m-1)` 이 파일 목록 대신 `*(.m-1)` 을 그대로 출력하거나 `no matches found` 로 죽으면
  → `BARE_GLOB_QUAL` 이 꺼진 환경이다. 개념은 유지되지만 **bare 문법을 쓸 수 없다**.
    `setopt | grep bareglob` 로 확인하고, 필요하면 `*(#q.m-1)` 형식을 쓴다
- bash·POSIX sh 에서 `echo *(.)` 가 파일 목록을 내놓으면
  → "퀄리파이어는 zsh 고유" 라는 범위 주장이 틀렸다
- `grep`·`sed` 같은 순수 regex 도구에 파일 mtime·권한으로 거르는 옵션이 있는 것을 발견하면
  → "regex 에는 대응물이 없다" 가 틀렸다. 단 `find -regex -mtime` 조합은 반례가 아니다 (아래 함정)
- `setopt nonomatch` 를 켠 뒤에도 0건 패턴이 에러를 내면
  → NOMATCH 가 0건 에러의 원인이라는 설명이 틀렸다

## 적용 범위

- `[실측]` zsh 5.9 / macOS(darwin 24). 퀄리파이어·NOMATCH·`(N)`·`(#q)` 전부 이 환경에서 확인
- `[실측]` bash 3.2.57 에서 퀄리파이어는 문법 오류. 0건은 에러가 아니라 패턴 그대로 통과
- `[추정]` fish·ksh 등 다른 셸은 확인하지 않았다. bash 도 5.x 계열은 돌려보지 않았다
- 퀄리파이어의 bare 형식은 `BARE_GLOB_QUAL` 이 켜진 zsh 에서만 성립한다. 꺼진 환경에서는
  `(#q...)` 형식을 쓴다 (이쪽은 `EXTENDED_GLOB` 만 요구)

## 함정

`find -regex ... -mtime -1` 은 이 노트의 반례가 아니다. 거기서 regex 가 하는 일은 여전히 이름 매칭
하나뿐이고, mtime 판정은 `find` 가 자기가 `stat()` 해서 한다. **속성을 보는 주체가 regex 가 아니다.**
glob 퀄리파이어와 구조가 같다 — 파일시스템을 읽는 쪽이 속성 필터를 제공한다.

`*(a|b)` 는 퀄리파이어처럼 보이지만 그룹이다. 괄호 안에 `|` 가 있으면 매뉴얼 규정상 퀄리파이어
해석 대상에서 제외된다.

`(N)` 은 "에러를 막는 장치" 인데, 그 장치를 파싱하는 옵션이 꺼지면 함께 무력화된다. 이때 `(N)` 은
글자 `N` 으로 읽혀서 `*.zsh(N)` 이 `*.zshN` 이라는 이름을 찾게 되고, 결국 **막으려던 그 에러가 난다.**
억제 장치는 억제 대상보다 먼저 파싱된다는 보장이 없다.

⚠️ zsh 의 0건 = 에러는 glob 의 보편 성질이 아니라 zsh 선택이다. bash 는 같은 상황에서 패턴을 글자
그대로 다음 명령에 넘긴다. `rm nope*` 가 bash 에서 "nope\* 라는 파일이 없다" 로 끝나는 반면
zsh 에서는 명령 자체가 실행되지 않는다.

💡 `find` 로 쓰던 조건을 zsh 에서는 한 줄로 줄일 수 있는 경우가 많다.
`find . -maxdepth 1 -type f -mtime +30 -name '*.log'` ≈ `*.log(.m+30)`.
