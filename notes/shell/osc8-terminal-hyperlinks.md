# OSC 8 — 터미널에서 보이는 글자와 링크 대상을 분리하기

> 좁은 화면에 긴 경로를 그대로 뿌리면 줄바꿈돼 레이아웃이 깨진다. OSC 8 이스케이프는
> 짧은 라벨만 화면에 그리고 전체 경로는 링크에 숨긴다. 미지원 터미널에서는 라벨만 남는다.

## 왜 그렇게 동작하나

터미널은 출력 바이트 중 특정 이스케이프 시퀀스를 화면에 그리지 않고 명령으로 해석한다.
OSC(Operating System Command) 8 은 그중 하이퍼링크를 여는 명령이다.

```
ESC ]8;; <URI> ESC \    ← 여기부터 링크 시작
보이는 글자
ESC ]8;; ESC \          ← 링크 끝 (URI 자리가 비면 닫는 뜻)
```

핵심은 **URI 가 화면 폭을 차지하지 않는다**는 점이다. 커서는 "보이는 글자" 만큼만 움직인다.
그래서 폭 계산·clip·정렬 로직은 라벨 길이만 신경 쓰면 된다.

미지원 터미널은 이 시퀀스를 무시하거나 버리므로 라벨이 평문으로 남는다. 링크가 안 될 뿐
화면이 깨지지는 않는다 — 점진적 향상(graceful degradation)이 성립하는 몇 안 되는 터미널 기능이다.

## 확인하는 방법

```bash
printf '\e]8;;file:///etc/hosts\e\\hosts 파일\e]8;;\e\\\n'
```

`hosts 파일` 만 보이고 클릭(보통 Cmd/Ctrl+클릭)하면 열리면 지원하는 것이다.
그대로 `\e]8;;...` 가 보이면 `printf` 가 이스케이프를 해석하지 않은 것이니 `%b` 나 `$'...'` 를 쓴다.

파이썬에서 쓸 때는 URI 를 반드시 인코딩한다.

```python
from urllib.parse import quote
link = f"\033]8;;file://{quote(path)}\033\\{label}\033]8;;\033\\"
```

## 함정

- ⚠️ **경로에 공백·한글이 있으면 인코딩 없이는 링크가 끊긴다.** 라벨은 멀쩡해 보이는데
  클릭만 안 되므로 원인을 찾기 어렵다.
- `file://` URI 는 절대 경로여야 한다. `~` 는 터미널이 확장해주지 않는다.
- 화면 폭을 계산하는 코드가 이스케이프까지 세면 라벨이 과도하게 잘린다. **폭 계산은 라벨에만**
  적용하고 이스케이프는 나중에 감싼다.
- 출력을 파일이나 파이프로 넘길 때는 이스케이프가 그대로 섞인다. 사람이 볼 화면이 아니면
  `isatty()` 로 판단해 링크를 빼는 편이 낫다.
- 💡 표시 텍스트가 대상과 완전히 무관해도 되기 때문에, 반대로 **어디로 가는지 숨기는 데도 쓸 수 있다.**
  신뢰할 수 없는 출처의 문자열을 그대로 터미널에 흘리면 안 되는 이유 중 하나다.

## 관련

- 색·굵기를 넣는 SGR(`ESC [ 1m` 등)도 같은 원리로 폭을 차지하지 않는다. 폭 계산 버그의
  단골 원인이 이 둘이다.
