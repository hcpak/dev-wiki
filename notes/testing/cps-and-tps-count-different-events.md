# CPS 와 TPS 는 다른 사건을 센다 — 연결 재사용을 허용하면 CPS 는 측정 자체가 성립하지 않는다

> CPS(connections per second)는 초당 **새로 수립되는 연결** 수, TPS(transactions per second)는 초당
> **처리되는 요청** 수다. keep-alive 로 한 연결이 여러 요청을 나르면 둘은 크게 갈라진다.
> 그래서 같은 런의 두 숫자에 서로의 이름을 붙이면, 값이 아니라 **측정 조건**을 잘못 말하게 된다.

## 왜 그렇게 동작하나

`[문서]` 두 지표가 세는 사건이 다르다. CPS 는 TCP 3-way handshake(TLS 면 그 위의 handshake까지)가
완료되는 빈도이고, TPS 는 이미 열린 연결 위에서 요청·응답 한 쌍이 끝나는 빈도다.
연결 하나가 요청 N 개를 나르면 `TPS ≈ N × CPS` 가 된다.

`[문서]` 그래서 **CPS 측정은 부하 도구에서 연결 재사용을 끈 상태에서만 성립한다.**
gatling 의 `shareConnections` 를 켜면 가상 유저들이 연결 풀을 공유해 재사용하므로,
목표 CPS 를 걸어도 실제 신규 연결 수는 그보다 훨씬 적게 발생한다 — 측정값이 관대해진다.

`[문서]` 병목 지점도 다르다. CPS 부하는 handshake·소켓 할당·포트 회수에 부딪히고,
TPS 부하는 요청 처리(파싱·라우팅·백엔드 응답 대기)에 부딪힌다. 그래서 CPS 를 올리다 보면
측정 **대상**이 아니라 **부하 발생 측**이 먼저 무너지는 일이 흔하다 — TIME_WAIT 소켓 고갈이 그 전형이다
(`net.ipv4.tcp_max_tw_buckets` 등이 상한을 만든다).

`[문서]` 한 부하 측정 기록에서 같은 조건의 런이 CPS 는 X, 최대 TPS 는 약 1.7X 로 남아 있었다.
두 숫자가 공존하는 것이 정상이고, **낮은 쪽(CPS)이 더 어려운 지표**다.
CPS 실측치를 TPS 라고 적으면 조건을 흐리는 동시에 성과를 낮게 적는 셈이 된다.

## 확인하는 방법

⚠️ 아래 명령은 이 노트를 쓴 시점에 실행하지 않았다 — 출력을 붙이기 전까지 `[실측]` 로 승격하지 않는다.

```
# 부하 중 신규 연결이 실제로 계속 생기는지 (CPS 조건이 성립하는지)
$ ss -tan state syn-recv | wc -l          # handshake 진행 중인 연결
$ ss -tan state established | wc -l       # 유지 중인 연결 — 낮게 머물면 재사용 없음

# 재사용이 일어나면 established 가 쌓이고 syn-recv 는 거의 0 에 머문다
$ nstat -az TcpPassiveOpens TcpActiveOpens   # 초당 증가분이 실제 CPS
```

## 이 노트가 틀렸다면

- 연결 재사용을 켠 채와 끈 채로 측정한 CPS 가 **같게** 나온다 → 도구가 재사용을 실제로 하지 않고 있다.
  이 노트의 전제(재사용 여부가 CPS 정의를 바꾼다)가 그 구성에서는 적용되지 않는다
- 같은 런에서 **TPS 가 CPS 보다 낮게** 기록된다 → 연결당 요청이 1 미만(연결만 맺고 요청을 안 보냄)이거나
  두 지표의 집계 창이 다르다. 값 비교 전에 집계 기준을 먼저 확인해야 한다
- `nstat` 의 `TcpPassiveOpens` 증가분이 도구가 보고한 CPS 와 크게 다르다 → 도구 보고값이 신규 연결 수가 아니다

## 적용 범위

TCP 기반 L4/L7 부하 측정. HTTP keep-alive 또는 연결 풀을 쓰는 클라이언트가 전제다.
UDP·QUIC 은 연결 개념이 달라 이 구분이 그대로 적용되지 않는다.

## 함정

- ⚠️ 부하 도구가 보고하는 "요청 수" 를 CPS 로 읽지 말 것. 연결 재사용 설정을 확인하지 않으면
  같은 로그가 두 지표 중 어느 것인지 알 수 없다
- ⚠️ CPS 측정에서 실패율이 오르면 측정 대상을 의심하기 전에 **부하 발생 측**의 소켓 상태를 먼저 본다
- 💡 이력서·보고서에 수치를 옮길 때는 값보다 **지표 이름과 측정 조건**이 먼저 검증 대상이다.
  아는 사람은 "그럼 다른 쪽 지표는 얼마인가" 로 바로 되짚는다
