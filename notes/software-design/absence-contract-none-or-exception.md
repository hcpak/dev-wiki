# 조회 API 가 "없음"을 `None` 으로 주는지 예외로 주는지는 시그니처에 없다 — 잘못 가정하면 도달 불가 코드가 남는다

> `get_x(id)` 를 호출한 쪽이 "못 찾으면 `None` 이 온다" 고 가정하고 `if x is not None:` 가드를 썼는데 실제 구현이 예외를 던지면, 그 가드는 **처음부터 참·거짓을 가릴 일이 없는 죽은 조건**이 된다. 정상 입력에서는 예외가 안 나므로 리뷰도 테스트도 통과하고, 예외가 나는 드문 입력에서만 전혀 다른 실패로 드러난다.

**상태**: 활성
**마지막 검증**: 2026-08-28

## 왜 그렇게 동작하나

`[코드]` 전형적인 형태는 이렇다.

```python
x = get_x(context, xid)                 # 없으면 raise NotFound (호출부는 모른다)
if x is not None and x['kind'] == WANTED:
    return True
else:
    return False
```

- `[코드]` 부재 표현은 **반환값 계약**이지 타입 시그니처가 아니다. 파이썬처럼 선언이 없는 언어에서는 호출부가 구현을 열어보지 않으면 알 수 없다.
- `[코드]` 잘못 가정한 가드는 **문법적으로 멀쩡하다.** 린터·정적 분석에 안 걸리고, 커버리지도 "그 줄을 지나갔다" 로 계산한다.
- `[코드]` 실제 실패는 가드가 아니라 **호출부의 바깥**에서 나타난다. 넓은 `except` 가 감싸고 있으면 엉뚱한 에러 메시지로 변환되고, 루프 안이라면 그 항목 하나 때문에 루프 전체가 중단된다.

증상 쪽에서 이 패턴을 알아보는 단서가 둘 있다.

- **"지원 안 하면 건너뛴다" 는 설계가 분명히 있는데, 특정 입력에서만 전체가 실패한다.** 건너뛰기 그물은 정해진 예외 종류만 잡고, 계약이 어긋난 예외는 그 그물을 빠져나간다.
- **에러 메시지에 사용자가 요청하지 않은 리소스의 식별자가 등장한다.** 내부 조회가 밖으로 새어 나온 것이다.

## 확인하는 방법

`[코드]` getter 구현에서 부재 처리를 직접 본다. 셋 중 하나다.

```
grep -n "NoResultFound\|\.one()\|\.first()\|return None\|raise .*NotFound" <getter 구현 파일>
```

- `.one()` + `except NoResultFound: raise ...NotFound` → **예외 계약**
- `.first()` 를 그대로 반환 → **`None` 계약**

`[코드]` 그다음 호출부의 `is not None` 가드가 도달 가능한지 본다. 예외 계약인데 가드가 있으면 그 가드는 죽은 코드다.

## 이 노트가 틀렸다면

- **getter 에 `None` 을 반환하는 경로가 실제로 있으면** → 가드는 죽은 코드가 아니다. 두 계약이 공존하는 구현일 수 있으니 분기별로 다시 봐야 한다.
- **예외를 잡아 정규화했는데도 증상이 그대로면** → 이 경로가 원인이 아니다.
- **넓은 `except` 가 이미 그 예외를 잡아 같은 결과로 변환하고 있으면** → 사용자 관점의 동작은 처음부터 같았다는 뜻이고, 고칠 가치는 가독성뿐이다.

## 적용 범위

- 부재를 반환값으로도 예외로도 표현할 수 있는 언어·프레임워크. 타입에 `Optional` 이 강제되는 환경에서는 컴파일 단계에서 걸린다.
- 호출부와 구현부가 **다른 저장소·다른 시점**에 작성된 경우 특히 잘 발생한다. 같은 사람이 같은 날 쓴 코드라면 계약을 알고 쓴다.

## 함정

- 💡 **호출 시그니처만 여러 번 고친 커밋 흔적은 신호다.** 인자 개수나 접근 경로를 며칠 사이에 두세 번 바꿨다면, 호출이 되게 만드는 데 집중했고 **반환·예외 계약은 확인되지 않았을** 가능성이 높다.
- ⚠️ **"정상 케이스에서 안 터진다" 가 검증을 통과시킨다.** 개발·검증 환경에서는 대상이 항상 존재하므로 예외 경로를 밟지 않는다. 드문 조건이 갖춰진 운영에서 처음 드러난다.
- ⚠️ 도달 불가 가드를 지우는 것만으로는 아무것도 안 고쳐진다. 계약을 어느 쪽으로 통일할지가 실제 결정이다.

## 처방

둘 중 하나로 통일한다. 섞어 두면 다음 사람이 같은 실수를 한다.

- **호출부에서 정규화** — 예외를 잡아 `None`/`False` 로 바꾼다. 판정 함수가 불리언만 반환한다는 계약을 호출부 6곳이 전제하고 있다면 이쪽이 외과적이다.
- **가드를 지우고 예외에 위임** — 부재가 정말 오류인 경우. 이때는 상위에서 그 예외를 의미 있게 다루는지 확인해야 한다.
