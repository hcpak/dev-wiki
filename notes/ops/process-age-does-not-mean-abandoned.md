# 오래 떠 있는 프로세스는 버려진 프로세스가 아니다 — 나이는 소유자를 말해주지 않는다

> 정리 대상을 고를 때 `ps` 의 경과 시간으로 줄을 세우면, 20일째 열려 있는 세션이
> 20일 전에 죽은 세션의 잔재로 보인다. 소유자를 판정하는 값은 나이가 아니라 **부모 pid 의 생존**이고,
> 이 둘은 서로 아무 관계가 없다.

**상태**: 활성
**마지막 검증**: 2026-08-14

## 왜 그렇게 동작하나

stdio 로 붙는 하위 프로세스(에디터·에이전트 도구가 띄우는 보조 서버 계열)는 부모가 살아 있는 동안
계속 살아 있다. 요청이 없으면 파이프를 읽으며 대기하므로 **CPU 0%, 나이만 늘어난다.**

- `[실측]` `etime` 은 기동 이후 경과 시간일 뿐이다. 부모가 언제 죽었는지, 지금 쓰이고 있는지에 대한
  정보를 전혀 담지 않는다. 장수 세션에서는 "오래됨" 과 "버려짐" 이 완전히 무상관이다.
- `[문서]` 부모가 먼저 죽으면 자식은 재부모화(reparent)된다. 그래서 **고아의 신호는 나이가 아니라
  `ppid` 가 1(또는 그 OS 의 수거 프로세스)로 바뀌어 있는 것**이다.
- `[실측]` 부모가 살아 있으면 `ppid` 는 원래 값 그대로다. 부모 pid 를 `ps` 목록에서 찾을 수 있는지만
  봐도 1차 판별이 끝난다.

여기서 한 걸음 더 나간다. **프로세스가 살아 있다는 것과 어떤 파일을 붙들고 있다는 것은 다른 질문**이다.
디렉토리를 지우려면 "이 경로를 인자로 들고 도는 프로세스가 있는가" 를 따로 세어야 한다.
설치 매니페스트만 보고 "참조 없음" 으로 판단하면, 그 경로로 이미 기동해 버린 프로세스를 놓친다.

- `[실측]` 실행 중 프로세스의 커맨드라인에는 그 경로가 그대로 박혀 있다(`--plugin-dir <경로>`,
  `-c <경로>/constraints.txt` 등). 매니페스트에서 빠진 옛 버전 디렉토리가 **커맨드라인에는 13개**
  남아 있는 상태가 실제로 있었다.

## 확인하는 방법

나이로 정렬한 목록은 판단 근거가 되지 못한다. 부모까지 같이 뽑는다.

```
$ ps -eo pid,ppid,etime,command | grep <server> | grep -v grep
   1194   1103   06:43:11  ... -c <cache>/<plugin>/<old-sha>/constraints.txt <server>
  90657  90637  20-06:17:49  ... <server>
```

`ppid` 를 `ps` 목록에서 되짚어 부모가 살아 있는지 본다. 살아 있으면 그 프로세스는 남의 세션 것이다.

```
$ ps -p 1103,90637 -o pid,etime,command | cut -c1-60
  PID     ELAPSED COMMAND
 1103    06:45:06 <에디터 세션 프로세스>
90637 20-06:17:49 <터미널 세션 프로세스>
```

진짜 고아만 세는 판정식은 이것이다. **부모가 프로세스 테이블에 없는 것.**

```
$ ps -eo pid,ppid,command | awk '$3 ~ /<server>/ {print $1, $2}' \
    | while read pid ppid; do ps -p $ppid >/dev/null || echo "고아: $pid"; done
(출력 없음 — 고아 0개)
```

지우려는 디렉토리는 **경로 문자열로** 참조를 센다.

```
$ ps -eo command | grep -c "<cache>/<plugin>/<old-sha>"
13
```

## 이 노트가 틀렸다면

- **`ppid` 가 1인데 정상 서비스 중인 프로세스가 있으면** → 고아 판정 기준으로 `ppid` 단독은 부족하다.
  의도적으로 데몬화(더블 포크)한 서비스가 여기 해당한다. 이 노트는 **부모가 붙잡고 쓰는 stdio 자식**에만 적용된다.
- **부모는 살아 있는데 그 부모가 이미 연결을 끊고 방치한 경우가 관측되면** → "부모 생존 = 사용 중" 이
  성립하지 않는다. 파이프가 끊겼는지는 `lsof -p <pid>` 로 stdin/stdout 상대편을 확인한다.
  `[추정]` 이 경우를 실제로 만나 본 적은 없다 — 확인하지 않았다.
- **커맨드라인에 경로가 안 박히는 방식(환경변수·설정파일 경유)으로 참조하는 프로그램이면** →
  `grep -c` 참조 계수가 0으로 나와도 사용 중일 수 있다. 그때는 `lsof +D <디렉토리>` 로 바꿔 센다.

## 적용 범위

- 부모가 stdio 로 붙들고 있는 보조 프로세스. 데몬·서비스 관리자가 띄운 프로세스는 대상이 아니다
- 재부모화 동작은 POSIX 공통이지만 수거 프로세스의 pid 는 OS 마다 다르다(리눅스는 1 또는 서브리퍼)
- 세션이 며칠~몇 주 단위로 열려 있는 작업 방식에서 특히 크게 어긋난다. 매일 닫는 환경이면 나이와
  소유자가 우연히 상관관계를 갖는다 — 그래서 이 함정은 **장수 세션에서만 드러난다**

## 함정

- ⚠️ `ps` 를 나이순으로 정렬해 "오래된 것 = 정리 대상" 목록을 만드는 순간 사고가 예약된다.
  실제로 12개를 정리 대상으로 잘못 분류했고, 부모를 추적해 보니 **고아는 0개**였다
- ⚠️ 유휴 상태의 stdio 자식은 CPU 0%·메모리 소량이라 `top` 에서도 죽은 것처럼 보인다.
  "아무 일도 안 하는 것 같다" 는 종료 근거가 아니다
- 💡 정리 스크립트에는 나이 조건 대신 **부모 부재 + 경로 참조 0** 두 조건을 넣는다.
  둘 다 명령 한 줄로 확인되고, 나이와 달리 틀릴 여지가 없다
- 💡 지우기 전에 "이걸 지우면 무엇이 깨지는가" 를 먼저 출력하게 만든다. 참조가 남아 있으면
  건너뛰고 이유를 찍는 루프가, 지운 뒤 복구하는 것보다 항상 싸다
